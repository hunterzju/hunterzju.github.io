trition依赖llvm和mlir,编译过程中会clone llvm仓库并切换到匹配分支，国内需要合适的代理；

编译过程参考官方文档：

## triton工具

源码bin目录下顶层应用：
- triton-opt
- triton-reduce
- triton-lsp
- triton-llvm-opt
- triton-tensor-layout

下面是每个工具的作用详解：

---

### 1. `triton-opt`

> **作用：Triton 的 IR 优化与转换工具（类似 `mlir-opt`）**

- 功能类似于 LLVM 的 `opt` 或 MLIR 的 `mlir-opt`。
- 接收 `.ttir`（Triton IR）或 `.ttgir`（Triton GPU IR）格式的输入。
- 允许你手动运行一系列 **pass（优化/转换）**，例如：
    - `--triton-gpu-pipeline`
    - `--convert-triton-to-llvm`
    - `--canonicalize`
- 常用于 **调试编译流程**、验证某个 pass 的效果，或生成特定阶段的 IR 快照。

示例：

```bash
triton-opt input.ttir --triton-gpu-decompose-op --convert-triton-to-llvm > output.ll
```

---

### 2. `triton-reduce`

> **作用：测试用例简化工具（Test-case Reducer）**

- 类似于 `creduce` 或 `bugpoint`，用于 **自动缩小能复现 bug 的最小 Triton 程序**。
- 当你发现某个 Triton 内核导致编译崩溃或错误结果时，可以用它从大内核逐步删减到最小复现代码。
- 内部使用 delta debugging 算法，结合用户提供的“判断是否仍触发 bug”的脚本。

使用场景：

```bash
triton-reduce --test-script=./check_bug.sh failing_kernel.py
```

---

### 3. `triton-lsp`

> **作用：Triton Language Server Protocol 服务**

- 为编辑器（如 VS Code、Vim）提供 **智能补全、跳转定义、错误提示等 IDE 功能**。
- 基于 [LSP](https://microsoft.github.io/language-server-protocol/) 标准实现。
- 目前 **仍在实验阶段**，社区支持有限，但未来可用于提升 Triton 内核开发体验。

配合 VS Code 插件使用（需手动配置 LSP 客户端指向 `triton-lsp`）。

---

### 4. `triton-llvm-opt`

> **作用：对 Triton 生成的 LLVM IR 进行进一步优化**

- 在 Triton 将 TTGIR 转换为 LLVM IR 后，会调用 LLVM 的优化 pipeline。
- `triton-llvm-opt` 是一个封装工具，用于 **单独运行 LLVM 层的优化 pass**（如 `instcombine`, `loop-unroll` 等）。
- 主要用于 **性能调优研究** 或 **调试 LLVM 后端行为**。

---

### 5. `triton-tensor-layout`

> **作用：分析或转换张量内存布局（Layout Transformation Tool）**

- Triton 的高性能依赖于 **自定义张量分块布局（如 `blocked`, `mma`, `shared`）**。
- 此工具可用于：
    - 打印某个 layout 的详细信息（如 swizzle 模式、线程分配）；
    - 验证 layout 转换是否合法；
    - 辅助开发新的 layout 策略（如针对 Hopper TMA 的 layout）。
- 对 **编译器开发者** 或 **高级内核优化者** 有用。

示例（假设支持 dump）：

```bash
triton-tensor-layout --layout="blocked(m=64,n=64)" --dump-strides
```

---

### 总结表格

|工具名|用途|用户类型|
|---|---|---|
|`triton-opt`|手动运行 Triton IR 优化 pass|编译器开发者 / 调试者|
|`triton-reduce`|自动缩小 bug 复现用例|贡献者 / 测试人员|
|`triton-lsp`|提供编辑器智能支持（LSP）|内核开发者（未来）|
|`triton-llvm-opt`|优化 Triton 生成的 LLVM IR|编译器后端开发者|
|`triton-tensor-layout`|分析/转换张量内存布局|高级优化专家|

## triton测试用例

`test`目录是项目的 MLIR / 转换 / 后端回归测试集合，按功能分成多个子目录，例如：
- `Analysis/`：与分析相关的 pass 和分析正确性测试（别名、对齐、分配、内存屏障等）。
- `Conversion/`：将 Triton/Tritongpu 等高层 IR 转换到 LLVM / PTX /后端格式的测试（cover 各种 lowering、编码和 target-specific 降级）。
- `Gluon/`：与 Gluon 前端或 Gluon 相关转换、编码或推断测试。
- `Hopper/`、`TritonGPU/`、`TritonNvidiaGPU/` 等：针对不同后端或硬件架构（Hopper, NVIDIA, AMD 等）的后端特性与生成的测试。
- `Triton/`：核心 Triton-level pass（canonicalize、combine、loop CSE、unroll、ops 等）的测试。
- `NVWS/`, `Proton/`, `Plugins/` 等：各自子系统的单元回归/转换测试。
- `Tools/`：工具级别的测试（如 `tensor_layout_print.mlir`）。

每个子目录通常包含若干 `.mlir` 测试文件（有时还有 `.in` / `.mlir.in` 模板），以及顶层的 [CMakeLists.txt](vscode-file://vscode-app/opt/visual-studio-code/resources/app/out/vs/code/electron-browser/workbench/workbench.html) 或 lit 配置来把它们纳入 lit 测试套件。

下面列出附件中几个子目录或典型文件并说明它们的意图与行为：

- Triton（核心 Triton pass）
    
    - 包含 [vecadd.mlir](vscode-file://vscode-app/opt/visual-studio-code/resources/app/out/vs/code/electron-browser/workbench/workbench.html)、`ops.mlir`、`canonicalize.mlir`、`loop-unroll.mlir` 等。目的：
        - 验证高层 Triton IR 的各类变换（合并、规范化、循环优化、broadcast reorder 等）。
        - vecadd.mlir：一个向量加 kernel 的示例，检查 pass 不产生诊断并可能会被一系列后端 passes 下降为更低阶 IR（注释部分展示了预期/示例的 lowered 形式）。
        - `verify-make-range.mlir`：常用于确保 `tt.make_range` 在不同情形下的语义/类型检查正确。
- Conversion
    
    - 测试从 Triton/Tritongpu 到 LLVM/目标 PTX 的转换（triton -> tritongpu -> llvm -> ptx），以及中间 encoding（coalesced encoding、encode/decode）和 tma/tensor-to-pointer 降级等。比如 `tritongpu_to_llvm_hopper.mlir` 会测试生成 Hopper (NVIDIA) PTX 的路径和特性。
    - 这些测试重点在于：转换后能否生成正确的内存访问、合适的同步、指令使用（copy_async、tma）和目标特有约束（数据布局、索引类型转换）。
- Analysis
    
    - 包含分析类测试（alias 分析、对齐检测、内存屏障 mbar、allocation 等）。这些文件通常会验证分析结果（如别名分析的结论或 pass 依赖的前置信息）以及传递诊断用于非法情况。
- [Gluon](vscode-file://vscode-app/opt/visual-studio-code/resources/app/out/vs/code/electron-browser/workbench/workbench.html)
    
    - Gluon 特定的表示/优化与前端相关的测试，通常用于确保前端到 Triton IR 的转换或 Gluon-specific pass 的正确性。
- [TritonGPU](vscode-file://vscode-app/opt/visual-studio-code/resources/app/out/vs/code/electron-browser/workbench/workbench.html) 与 [TritonNvidiaGPU](vscode-file://vscode-app/opt/visual-studio-code/resources/app/out/vs/code/electron-browser/workbench/workbench.html)
    
    - 更靠近硬件后端的测试：验证 warp specialization、atomic patterns、accelerate-matmul、accumulator init 等后端生成与 scheduling 相关的变换。
- [NVWS](vscode-file://vscode-app/opt/visual-studio-code/resources/app/out/vs/code/electron-browser/workbench/workbench.html), [Proton](vscode-file://vscode-app/opt/visual-studio-code/resources/app/out/vs/code/electron-browser/workbench/workbench.html), [Plugins](vscode-file://vscode-app/opt/visual-studio-code/resources/app/out/vs/code/electron-browser/workbench/workbench.html) 等
    
    - `NVWS` 可能是和某些 NV-specific workload scheduling/warp-group 的转换；
    - `Proton` 是第三方/外部组件的集成测试（例如生成 `protongpu`）；
    - `Plugins` 测试加载/使用 plugin 的行为（例如测试 plugin 提供的 passes/diagnostics）。

测试用例demo：
```mlir
module {

tt.func @add_kernel__Pfp32_Pfp32_Pfp32_i32_i32_i32__(%arg0: !tt.ptr<f32>, %arg1: !tt.ptr<f32>, %arg2: !tt.ptr<f32>, %arg3: i32, %arg4: i32, %arg5: i32) {

%0 = tt.get_program_id x : i32

%c256_i32 = arith.constant 256 : i32

%1 = arith.muli %0, %c256_i32 : i32

%2 = tt.make_range {end = 256 : i32, start = 0 : i32} : tensor<256xi32>

%3 = tt.splat %1 : i32 -> tensor<256xi32>

%4 = arith.addi %3, %2 : tensor<256xi32>

%5 = tt.splat %arg3 : i32 -> tensor<256xi32>

%6 = arith.cmpi slt, %4, %5 : tensor<256xi32>

%7 = tt.splat %arg0 : !tt.ptr<f32> -> tensor<256x!tt.ptr<f32>>

%8 = tt.addptr %7, %4 : tensor<256x!tt.ptr<f32>>, tensor<256xi32>

%9 = tt.splat %arg1 : !tt.ptr<f32> -> tensor<256x!tt.ptr<f32>>

%10 = tt.addptr %9, %4 : tensor<256x!tt.ptr<f32>>, tensor<256xi32>

%cst = arith.constant 0.000000e+00 : f32

%11 = tt.splat %cst : f32 -> tensor<256xf32>

%c0_i32 = arith.constant 0 : i32

%c32_i32 = arith.constant 32 : i32

%15:3 = scf.for %arg6 = %c0_i32 to %arg4 step %c32_i32 iter_args(%arg7 = %11, %arg8 = %8, %arg9 = %10) -> (tensor<256xf32>, tensor<256x!tt.ptr<f32>>, tensor<256x!tt.ptr<f32>>) : i32 {

%cst_0 = arith.constant 0.000000e+00 : f32

%18 = tt.splat %cst_0 : f32 -> tensor<256xf32>

%19 = tt.load %arg8, %6, %18 : tensor<256x!tt.ptr<f32>>

%cst_1 = arith.constant 0.000000e+00 : f32

%20 = tt.splat %cst_1 : f32 -> tensor<256xf32>

%21 = tt.load %arg9, %6, %20 : tensor<256x!tt.ptr<f32>>

%22 = arith.addf %19, %21 : tensor<256xf32>

%23 = arith.addf %arg7, %22 : tensor<256xf32>

%24 = tt.splat %arg5 : i32 -> tensor<256xi32>

%25 = tt.addptr %arg8, %24 : tensor<256x!tt.ptr<f32>>, tensor<256xi32>

%26 = tt.splat %arg5 : i32 -> tensor<256xi32>

%27 = tt.addptr %arg9, %26 : tensor<256x!tt.ptr<f32>>, tensor<256xi32>

scf.yield %23, %25, %27 : tensor<256xf32>, tensor<256x!tt.ptr<f32>>, tensor<256x!tt.ptr<f32>>

}

%16 = tt.splat %arg2 : !tt.ptr<f32> -> tensor<256x!tt.ptr<f32>>

%17 = tt.addptr %16, %4 : tensor<256x!tt.ptr<f32>>, tensor<256xi32>

tt.store %17, %15#0, %6 : tensor<256x!tt.ptr<f32>>

tt.return

}

}
```

vecadd的具体解释：
```
函数签名（简化）： tt.func @add_kernel__(%arg0: !tt.ptr<f32>, %arg1: !tt.ptr<f32>, %arg2: !tt.ptr<f32>, %arg3: i32, %arg4: i32, %arg5: i32)

%arg0 — 输入指针 A（f32* 风格）
%arg1 — 输入指针 B
%arg2 — 输出指针 C
%arg3 — 用作有效长度（用于比较索引判断越界）
%arg4 — 循环上界（用于 scf.for 的 to），代表要处理的块/步数上限
%arg5 — 指针在循环中每次迭代的偏移（用于 tt.addptr 增量）
主要步骤：

%0 = tt.get_program_id x : i32

取得当前 program（线程块/CTA）在 x 维上的 id。
计算每个 program 的基索引：

%c256_i32 = 256
%1 = %0 * 256
%2 = tt.make_range {0..256} → 生成 0..255 的索引向量（tensor<256xi32>）
%3 = tt.splat %1 → 把基索引广播成 tensor<256xi32>
%4 = %3 + %2 → 每 lane 的全局索引 = program_id * 256 + lane_index（0..255）
结论：每个 program 管理 256 个连续元素的“矢量 lanes”。

越界掩码：

%5 = splat %arg3
%6 = arith.cmpi slt, %4, %5 -> tensor<256xi1>
%6 是 per-lane 的布尔掩码：当全局索引 < 长度（arg3）时为真。用于安全 load/store。
生成每-lane 的指针：

把传入的指针 %arg0/%arg1 广播为 tensor<256x!tt.ptr<f32>>
%8 = tt.addptr %7, %4 （把 base pointer + per-lane 索引 => 每 lane 的元素指针）
%10 同理为 B 的 per-lane 指针
初始化累加器：

%11 = splat 0.0 : tensor<256xf32>
主循环（分块累加）：

scf.for %arg6 = 0 to %arg4 step 32 iter_args(%arg7 = %11, %arg8 = %8, %arg9 = %10) -> ...
这里使用 step=32：表示每次迭代向前移动 32（可能是按向量化或内存访问分块）。
迭代时携带三个迭代变量：当前累加器（tensor<256xf32>）和两个“移动后的”指针（tensor<256x!tt.ptr<f32>>）。
循环体：
使用 tt.load %arg8, %6, %18：从 A 指针（按 lane）加载 256 个 float，带掩码 %6（超界被屏蔽）。
同理加载 B。
%22 = arith.addf %19, %21 ：对 A 和 B 做逐 lane 相加（256 元素张量）。
%23 = arith.addf %arg7, %22 ：把结果累加到累加器（如果多次迭代，会把每轮加载的部分加到累加器）。
通过 tt.addptr 和 arg5（偏移量）更新两个指针（为下一次迭代准备）。
yield 返回更新后的累加器和指针。
语义：对于一个 program 的那 256 个 lanes，循环每次加载（按 step=32）一段数据、累加到累加器，直到循环结束。
结束后：

计算输出指针：%16 = splat %arg2; %17 = addptr %16, %4
tt.store %17, %15#0, %6 ：将累加器（%15#0 即最终 tensor<256xf32>）写回输出指针，使用同样的掩码 %6（避免越界写）。
tt.return
总结：这是标准的 blocked vector-add 内核实现模式：

程序按 program_id 分配第 program_id*256 .. +255 区间。
每个 lane 对应一个元素索引；使用掩码避免越界访问。
通过一个以 32 为步长的内循环做分块加载/累加（可能对应硬件分段加载或预取/分批计算），最后写回。
```
