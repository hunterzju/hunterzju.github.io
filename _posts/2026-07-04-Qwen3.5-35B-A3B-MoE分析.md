# Qwen3.5-35B-A3B MoE 阶段源码与数据流分析

## 1. 模型概述

Qwen3.5-35B-A3B 是一个基于 Mixture of Experts (MoE) 架构的大语言模型，采用混合注意力机制（线性注意力 + 全注意力）。

| 参数          | 值                        |
| ----------- | ------------------------ |
| 总参数量        | ~35B                     |
| 激活参数量       | ~3B                      |
| 架构类型        | MoE (Mixture of Experts) |
| 专家总数        | 256                      |
| 每token激活专家数 | 8                        |
| 稀疏激活比例      | 3.125% (8/256)           |

## 4. MoE 数据流全图
源码
```python
class Qwen3_5MoeSparseMoeBlock(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.gate = Qwen3_5MoeTopKRouter(config)
        self.experts = Qwen3_5MoeExperts(config)
        self.shared_expert = Qwen3_5MoeMLP(config, intermediate_size=config.shared_expert_intermediate_size)
        self.shared_expert_gate = torch.nn.Linear(config.hidden_size, 1, bias=False)

    def forward(self, hidden_states: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
        batch_size, sequence_length, hidden_dim = hidden_states.shape
        hidden_states_reshaped = hidden_states.view(-1, hidden_dim)
        shared_expert_output = self.shared_expert(hidden_states_reshaped)
        _, routing_weights, selected_experts = self.gate(hidden_states_reshaped)
        expert_output = self.experts(hidden_states_reshaped, selected_experts, routing_weights)

        shared_expert_output = F.sigmoid(self.shared_expert_gate(hidden_states_reshaped)) * shared_expert_output

        expert_output = expert_output + shared_expert_output
        expert_output = expert_output.reshape(batch_size, sequence_length, hidden_dim)
        return expert_output
```

### 5.2 Shared Expert（共享专家）

**源码**: `Qwen3_5MoeMLP.forward` (line 734-736)
```python
class Qwen3_5MoeMLP(nn.Module):
    def __init__(self, config: Qwen3_5MoeConfig, intermediate_size: int):
        super().__init__()
        self.config = config
        self.hidden_size = config.hidden_size
        self.intermediate_size = intermediate_size
        self.gate_proj = nn.Linear(self.hidden_size, self.intermediate_size, bias=False)
        self.up_proj = nn.Linear(self.hidden_size, self.intermediate_size, bias=False)
        self.down_proj = nn.Linear(self.intermediate_size, self.hidden_size, bias=False)
        self.act_fn = ACT2FN[config.hidden_act]

    def forward(self, x):
        down_proj = self.down_proj(self.act_fn(self.gate_proj(x)) * self.up_proj(x))
        return down_proj
```

## 7. 共享专家（Shared Expert）详细分析

### 7.1 源码结构

**源码**: `Qwen3_5MoeMLP` (line 723-736) + `Qwen3_5MoeSparseMoeBlock` (line 798-817)

```python
# 初始化
self.shared_expert = Qwen3_5MoeMLP(config, intermediate_size=config.shared_expert_intermediate_size)
self.shared_expert_gate = torch.nn.Linear(config.hidden_size, 1, bias=False)

# 前向计算
shared_expert_output = self.shared_expert(hidden_states_reshaped)
shared_expert_output = F.sigmoid(self.shared_expert_gate(hidden_states_reshaped)) * shared_expert_output
```

### 7.2 SwiGLU MLP 计算流程

共享专家采用 SwiGLU 结构，包含三个独立的线性层：

```
输入: hidden_states_reshaped [B*S, 2048]
    │
    ├───→ gate_proj.weight [512, 2048] ──→ [B*S, 512] ──→ SiLU ──→ ┐
    │                                                                ├──→ × ──→ [B*S, 512]
    └───→ up_proj.weight [512, 2048] ──────→ [B*S, 512] ───────────┘
                                                                    │
                                                                    ▼
                                                    down_proj.weight [2048, 512]
                                                                    │
                                                                    ▼
                                                        [B*S, 2048] (shared_expert_output)
```

| 步骤 | 算子 | 输入 | 输出 | 权重维度 |
|------|------|------|------|----------|
| 1 | `gate_proj` (Linear) | `[B*S, 2048]` | `[B*S, 512]` | `[512, 2048]` |
| 2 | `up_proj` (Linear) | `[B*S, 2048]` | `[B*S, 512]` | `[512, 2048]` |
| 3 | `silu(gate_proj)` | `[B*S, 512]` | `[B*S, 512]` | - |
| 4 | `element-wise mul` | `[B*S, 512]` × `[B*S, 512]` | `[B*S, 512]` | - |
| 5 | `down_proj` (Linear) | `[B*S, 512]` | `[B*S, 2048]` | `[2048, 512]` |

### 7.3 共享专家门控计算

门控信号来自原始输入，而非共享专家的输出：

```
hidden_states_reshaped [B*S, 2048]
    │
    └───→ shared_expert_gate.weight [1, 2048] ──→ [B*S, 1] ──→ sigmoid ──→ [B*S, 1] (gate_value)
                                                                              │
shared_expert_output [B*S, 2048] ─────────────────────────────────────────────┘
                                                                              │
                                                                              ▼
                                                    gate_value × shared_expert_output [B*S, 2048]
```

| 步骤 | 算子 | 输入 | 输出 | 说明 |
|------|------|------|------|------|
| 6 | `shared_expert_gate` (Linear) | `[B*S, 2048]`, weight `[1, 2048]` | `[B*S, 1]` | 独立于共享专家的门控信号 |
| 7 | `sigmoid` | `[B*S, 1]` | `[B*S, 1]` | 值域 (0, 1) |
| 8 | `element-wise mul (broadcast)` | `[B*S, 1]` × `[B*S, 2048]` | `[B*S, 2048]` | 每个token所有维度乘以同一标量 |

### 7.4 关键设计特点

1. **SwiGLU 结构**: gate_proj 和 up_proj 是独立的线性层，而非合并为一个大矩阵
2. **独立门控**: 门控信号来自原始输入 `hidden_states_reshaped`，每个token独立决定共享专家输出的权重
3. **无路由开销**: 共享专家不经过 Router，所有token都经过相同的共享专家
4. **参数量**: `512×2048 + 512×2048 + 2048×512 + 1×2048 = 3,147,776`

## 8. 稀疏路由专家（Sparse Experts）详细分析

### 8.1 总体架构

```
Qwen3_5MoeSparseMoeBlock
├── Qwen3_5MoeTopKRouter  → 选择每个token应该路由到哪些专家
├── Qwen3_5MoeExperts      → 被选中的专家进行前向计算
└── (shared_expert)        → 共享专家（见第7节）
```

### 8.2 Router 详细计算流程

**源码**: `Qwen3_5MoeTopKRouter` (line 779-795)

#### 8.2.1 权重结构

```python
self.weight = nn.Parameter(torch.zeros(256, 2048))  # [num_experts, hidden_size]
```

#### 8.2.2 计算流程

```
hidden_states [B*S, 2048]
    │
    ▼
F.linear(hidden_states, weight)  # weight [256, 2048]
    │
    ▼
router_logits [B*S, 256]  # 每个token对256个专家的原始分数
    │
    ▼
softmax(dim=-1)
    │
    ▼
router_probs [B*S, 256]  # 归一化为概率分布
    │
    ▼
topk(k=8)
    │
    ├─→ top_value [B*S, 8]   # 概率最高的8个值
    └─→ indices [B*S, 8]     # 对应的专家索引
          │
          ▼
top_value /= top_value.sum(dim=-1, keepdim=True)
          │
          ▼
router_scores [B*S, 8]  # 归一化后的路由权重（sum=1）
```

| 步骤 | 算子 | 输入 | 输出 | 说明 |
|------|------|------|------|------|
| 1 | `reshape` | `[B*S, 2048]` | `[B*S, 2048]` | 展平 batch 和 seq 维度 |
| 2 | `F.linear(hidden, weight)` | hidden `[B*S, 2048]`, weight `[256, 2048]` | `router_logits [B*S, 256]` | 线性映射 |
| 3 | `softmax(dim=-1)` | `[B*S, 256]` | `router_probs [B*S, 256]` | 归一化为概率 |
| 4 | `topk(k=8)` | `[B*S, 256]` | `top_value [B*S, 8]`, `indices [B*S, 8]` | 选出8个活跃专家 |
| 5 | `normalize` | `top_value [B*S, 8]` | `router_scores [B*S, 8]` | 权重归一化(sum=1) |

### 8.3 Experts 详细计算流程

**源码**: `Qwen3_5MoeExperts` (line 740-776)

#### 8.3.1 权重结构（3D Tensor）

```python
# gate_up_proj: 256个专家的 gate + up 合并投影
self.gate_up_proj = nn.Parameter(torch.empty(256, 1024, 2048))  # [num_experts, 2*intermediate_dim, hidden_dim]

# down_proj: 256个专家的下投影
self.down_proj = nn.Parameter(torch.empty(256, 2048, 512))       # [num_experts, hidden_dim, intermediate_dim]
```

#### 8.3.2 输入

- `hidden_states [B*S, 2048]`
- `top_k_index [B*S, 8]` — 每个token选中的8个专家索引
- `top_k_weights [B*S, 8]` — 对应的归一化路由权重

#### 8.3.3 Step 1: 构建专家掩码

```python
expert_mask = torch.nn.functional.one_hot(top_k_index, num_classes=256)
expert_mask = expert_mask.permute(2, 1, 0)
expert_hit = torch.greater(expert_mask.sum(dim=(-1, -2)), 0).nonzero()
```

```
top_k_index [B*S, 8]
    │
    ▼
one_hot(top_k_index, 256)
    │
    ▼
expert_mask [B*S, 8, 256]  # 每个token的8个专家位置设为1
    │
    ▼
permute(2, 1, 0)
    │
    ▼
expert_mask [256, 8, B*S]  # 第一维变为专家维度
    │
    ▼
sum(dim=(-1, -2)) → nonzero()
    │
    ▼
expert_hit [N_active, 1]  # 哪些专家被至少一个token选中
```

| 步骤 | 算子 | 输入 | 输出 | 说明 |
|------|------|------|------|------|
| 1a | `one_hot(top_k_index, 256)` | `[B*S, 8]` | `[B*S, 8, 256]` | 每个token的8个专家位置设为1 |
| 1b | `permute(2, 1, 0)` | `[B*S, 8, 256]` | `[256, 8, B*S]` | 第一维变为专家维度 |
| 1c | `sum → nonzero` | `[256, 8, B*S]` | `expert_hit [N_active, 1]` | 哪些专家被选中 |

#### 8.3.4 Step 2: 按专家循环计算

对每个被选中的专家 `expert_idx`:

```python
top_k_pos, token_idx = torch.where(expert_mask[expert_idx])
current_state = hidden_states[token_idx]
gate, up = nn.functional.linear(current_state, self.gate_up_proj[expert_idx]).chunk(2, dim=-1)
current_hidden_states = self.act_fn(gate) * up
current_hidden_states = nn.functional.linear(current_hidden_states, self.down_proj[expert_idx])
current_hidden_states = current_hidden_states * top_k_weights[token_idx, top_k_pos, None]
final_hidden_states.index_add_(0, token_idx, current_hidden_states.to(final_hidden_states.dtype))
```

```
expert_mask[expert_idx] [8, B*S]
    │
    ▼
where(expert_mask[expert_idx])
    │
    ├─→ token_idx [T]    # 该专家对应的token索引
    └─→ top_k_pos [T]    # 路由位置（第几个专家）
          │
          ▼

    │
    ▼

    │
    ▼

    │
    ▼
[T, 1024]
    │
    ▼
chunk(2)
    │
    ├─→ gate [T, 512]
    └─→ up [T, 512]
          │
          ▼
silu(gate) * up
    │
    ▼
[T, 512]
    │
    ▼
nn.functional.linear(down_proj[expert_idx])  # weight [2048, 512]

[T, 2048]
```

| 2b | `hidden_states[token_idx]` | `[B*S, 2048]` | `current_state [T, 2048]` | 提取被路由到该专家的token |
| 2c | `nn.functional.linear(gate_up_proj)` | `[T, 2048]`, weight `[1024, 2048]` | `[T, 1024]` | gate + up 合并投影 |
| 2d | `chunk(2)` | `[T, 1024]` | `gate [T, 512]` + `up [T, 512]` | 分割为门控和上投影 |
| 2e | `silu(gate)` | `[T, 512]` | `[T, 512]` | SiLU 激活 |
| 2f | `element-wise mul` | `[T, 512]` × `[T, 512]` | `[T, 512]` | SwiGLU: `act(gate) × up` |
| 2g | `nn.functional.linear(down_proj)` | `[T, 512]`, weight `[2048, 512]` | `[T, 2048]` | 下投影恢复维度 |
| 2h | `element-wise mul` | `[T, 2048]` × scalar | `[T, 2048]` | × routing weight |
| 2i | `index_add_` | `final [B*S, 2048]` ← `[T, 2048]` | 累加到对应位置 | 汇总所有专家结果 |

## 9. 关键设计特点

1. **SwiGLU 激活**: 所有专家（稀疏 + 共享）均采用 `silu(gate) × up` 的 SwiGLU 结构
2. **共享专家门控**: 共享专家输出通过 sigmoid 门控进行加权，而非直接相加
3. **稀疏专家归一化**: 路由权重经 softmax + 归一化处理，确保 sum=1
4. **循环计算**: 稀疏专家按被选中专家逐个循环计算，而非并行处理全部256个专家
5. **GPTQ 量化**: 模型采用 GPTQ 4-bit 量化，`dynamic` 配置中排除了 lm_head、embed_tokens、attn、shared_expert、mtp、visual 等模块
6. **稀疏激活**: 256个专家中仅8个被激活，计算量降低至 3.125%
7. **索引累加**: 使用 `index_add_` 将多个专家的结果累加到正确位置
